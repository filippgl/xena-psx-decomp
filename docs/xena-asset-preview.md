# Оригинальная Зена: предпросмотр, экспорт и апскейл

Обновлено 2026-10-22. Игровой EXE и исходные BIN/CUE не изменялись.

## Открыть результат

Из корня рабочей папки запустить `Preview-Xena.cmd`, либо открыть
`decomp/build/xena-preview/preview.html` в браузере. Сервер и интернет
для просмотра не нужны. Доступны все 81 клип, выбор кадра, воспроизведение,
поворот мышью, масштаб, иерархия и переключатель оригинал / 4×.

Изображения для сравнения:

- `build/xena-upscale/comparison.png`: оригинал слева, апскейл справа.
- `build/xena-upscale/xena-atlas-4x.png`: полный атлас, 2048×2048 RGBA.
- `build/xena-upscale/textures/`: 18 отдельных текстур после апскейла.
- `build/xena-preview/browser-qa.png`: просмотрщик в настоящем браузере.

## Что экспортировано

В `build/xena-preview/`:

- `xena-original.gltf`: модель с исходными текстурами.
- `xena-4x.gltf`: та же модель с апскейлом.
- `xena.bin`: общий бинарный буфер геометрии и анимаций.
- `page-0.png` … `page-2.png`: исходные страницы 256×256.
- `page-0-4x.png` … `page-2-4x.png`: страницы 1024×1024.

При переносе glTF нужно копировать вместе с `.bin` и соответствующими
PNG. Все пути относительные. Внутри 33 mesh-части, 426 треугольников,
иерархия трансформаций и 81 анимация. Дополнительные узлы геометрии
позволяют скрывать экипировку без скрытия дочерних частей иерархии.
Материалы используют `KHR_materials_unlit`, ближайшую фильтрацию и alpha mask.

Это glTF для дальнейшего импорта, не проверенный Unity prefab. Unity Editor
в этой сессии не запускался; glTF-импортёр не устанавливался.

Экспортирует выбранную конверсию координат Y-up и **условный** масштаб
400 исходных единиц на метр. Это настройка просмотра, не установленный
физический масштаб игры. Его можно изменить:

```powershell
node tools/export_xena_gltf.mjs --units-per-meter 400
```

30 шагов/с в glTF также являются условием экспорта. Кадры используют STEP,
последняя поза удерживается один шаг. Частота исходного планировщика,
root motion по уровню и игровые переходы ещё требуют отдельного исследования.

## Апскейл

Использован встроенный imagegen через навык imagegen. Точный запрос сохранён
в `build/xena-upscale/prompt.txt`. Исходный атлас извлечён из 18 TIM в XENA.STM
в единую сетку 512×512 без перестановки UV. Сырые результаты AI сохранены
отдельно: `xena-atlas-ai-v1.png`.

Генератор вернул 1254×1254. Итоговые 2048×2048 получены регистрацией
18 участков к исходным прямоугольникам и бикубическим масштабированием;
это не заявление о нативной генерации 2048×2048. Измеренные координаты
версии v1 находятся в `tools/preview/xena-upscale-registration-v1.json`.
При новой генерации регистрацию нужно проверить заново.

После выравнивания восстановлена исходная alpha-маска в точном масштабе 4×.
Проверены все 4 194 304 пикселя результата: несовпадений маски нет.
Исходная пиксельная форма прозрачных краёв при этом сохраняется.
Цветовые детали восстановлены AI и отличаются от оригинала; вариант
предназначен для ремастера, исходные текстуры доступны отдельно.

| Проверка | Результат |
| --- | --- |

| SMA против исходных инструкций | 1674 кадра / 7838 команд, PASS |
| Мировые матрицы против исходных инструкций | 55 242 матрицы, PASS |
| Свежий native runtime | 64 локальные позы частей и 66 матриц, PASS |
| UV-углы против загруженных текстур | Нет ссылок на незагруженные участки |
| glTF | 617 706 сравнений вершин, максимальная ошибка 0.910003 единицы PS1 |
| Alpha апскейла | 0 несовпадений |
| Браузер | Офлайн-загрузка, 81 клип, кадры, воспроизведение, текстуры, иерархия — PASS |

glTF использует исходные локальные углы и подгоняет локальные положения
к уже рассчитанным исходным положениям суставов. Это устраняет накопление
ошибки целочисленного округления трансляций. Вращения glTF остаются float,
поэтому не совпадают побитно с фиксированной математикой PS1. При условном
масштабе 400 единиц/м максимальное измеренное отклонение — около 2.28 мм.
Это внутренняя проверка данных, не Khronos conformance validation.

Native-референсы получены на `build/port/xena-console.exe`, время изменения
2026-10-22 21:11:35 по Москве (`2026-10-22T18:11:35.259Z`). Проверены кадры
9000 и 9200 первого уровня, состояние покоя. Корневая часть управляется
игровым миром; остальные 32 части совпали с декодированными позами.
Это сравнение с существующим PC runtime, не с эмулятором PS1.

Дополнительно установлен смысл видимости: массив `context+0xC` содержит
флаги **скрытия**, 0 означает рисовать. Подтверждено веткой
`func_800118F0` в `0x80011940–0x8001195C`. В свежем покое скрыты части
31 и 32. Эта исходная маска используется для независимого просмотра
каждого клипа; переключение экипировки игровой логикой отдельно не перенесено.

## Воспроизвести локально

Из `decomp/`, Node.js 22:

```powershell
node tools/build_xena_assets.mjs --native-reference --browser
```

Без флагов не запускаются PC runtime и Chrome. Команда не обращается к AI
или интернету; апскейл восстанавливается из уже сохранённой версии imagegen.
Для его повторной сборки нужны `build/xena-upscale/xena-atlas-ai-v1.png`
и регистрация v1. Если AI-результата нет, строится исходная модель.

Полные результаты проверок: `build/animation-audit/*verification.json`,
`build/animation-reference/verification.json`,
`build/xena-preview/gltf-verification.json`,
`build/xena-preview/browser-verification.json`,
`build/xena-upscale/verification.json`.

Все оригинальные и производные игровые ресурсы остаются в игнорируемом
`build/`, вне исходного кода. Следующий этап: проверка импорта в Unity,
эталонные видеозаписи из эмулятора, затем геометрия и коллизии первой комнаты.
