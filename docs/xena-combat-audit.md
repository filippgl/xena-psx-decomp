# Бой: проверенные данные и границы прототипа

`node tools/capture_combat_reference.mjs` запускает существующий нативный порт
с явным сценарием кнопок и сохраняет 251 RAM-снимок через два видеокадра.
Сценарий, EXE и его время изменения записываются в `build/combat-reference/capture.json`.
`node tools/inspect_xena_combat.mjs` сравнивает все локальные позиции и повороты
32 частей без мирового корня с исходными SMA: 48 192 компонента совпали.
Это проверка нативного порта, не консоли/эмулятора PS1.

| Действие | Наблюдаемая цепочка слотов | Кадры клипов |
| --- | --- | --- |
| Меч, три нажатия Cross | `51 → 52 → 3A` | 15, 20, 23 |
| Нога, три нажатия Square | `61 → 62 → 5A` | 18, 31, 22 |
| Блок Circle | `80 → 00` после отпускания | 28, стойка |

Во время контрольных серий переходы на следующий удар наблюдались после кадров
9/9 для меча и 8/21 для ноги (с нуля). Это конкретные наблюдения, не доказательство
самого раннего разрешённого перехода. Смешанная серия проходит через мост `57`
и возобновление `62` с промежуточного кадра; её точные правила пока не перенесены.
Временные поля контекста SMA `24/26` описывают движение и не объявляются флагами урона.

Исходная обработка `8006A6E8` использует данные класса объекта по `+3C` и
преобразования частей. Боевые объёмы, урон, отталкивание и точные окна попаданий
ещё требуют отдельного аудита. Параметры учебного манекена Unity не заменяют эти
данные и не доказывают совпадение сложности с оригиналом.
