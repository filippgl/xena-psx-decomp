# Xena: импорт оригинальных ресурсов в Unity

## Установка Unity (2026-10-22)

В корне папки игры подготовлен `Install-Xena-Unity.cmd`. Он скачивает
[Unity 6.3 LTS 6000.3.25f1](https://unity.com/releases/editor/whats-new/6000.3.25f1),
проверяет цифровую подпись издателя и устанавливает Editor в
`Unity63` в корне папки игры. Затем проверяет Windows standalone
support и запускает настоящий импорт с проверкой анимаций. Установка использует
[официальные параметры командной строки](https://docs.unity3d.com/6000.3/Documentation/Manual/InstallingUnity.html).

**Обновление 2026-10-23:** Unity установлен, лицензия Personal активна. Первая
установка в длинный путь потеряла 666 файлов: путь к исходнику URP с `.meta`
достигал 271 символа. Это вызвало `CS0246 MaterialReferenceChanger`. Unity
переустановлен в короткую папку `Unity63`, недостающие файлы восстановлены.
Код URP.Editor, Xena.Assets и Xena.Assets.Editor успешно скомпилирован Roslyn
по настоящим сборкам установленного Unity. Это проверка API, отдельно от импорта.

Если редактор сообщит об отсутствии лицензии, потребуется вход и активация
вашей лицензии через [Unity Hub](https://unity.com/download). После активации
повторный запуск CMD использует уже установленный Editor. Для открытия проекта
подготовлен `Open-Xena-Unity.cmd`. Успех проверки подтверждается только свежим
`decomp/build/unity-import/editor-verification.json` со статусом PASS.

После снятия ограничений сессии настоящий Editor запустился успешно. Лицензия
не потребовала изменений. `editor-verification.json` — **PASS**: 33 меша Зены,
81 AnimationClip, 1674 кадра и 115 506 сравнений трансформаций; локация — 74 меша,
3995 треугольников. Обе сцены созданы и сохранены.

`render-verification.json` — **PASS** на RTX 4070 SUPER / Direct3D 12.
Проверены рендеринг Зены с оригинальными и 4× текстурами, другая поза и первая
локация. Снимки `unity-*.png` находятся рядом с отчётом; снимки модели и локации
просмотрены. Шейдер компилируется, кадры непустые, ошибочного розового материала
нет. Это проверка ресурсов; поведение игры ещё не реализовано.

## Подготовленный проект

Подготовлен первый [прототип перемещения](movement-prototype.md) на оригинальном
уровне: **Play-Unity-Prototype.cmd** запускает Windows-сборку без Editor.
WASD, мышь, бег, прыжок, геймпад и пауза проверены настоящим запуском.
Отдельная сцена — `Level01MovementPrototype.unity`; исходные просмотры сохранены.

Если Unity Hub пишет, что проектов нет, нажмите **Add / Добавить → Add project
from disk / Добавить проект с диска** и выберите
`G:\Games\Xena Warrior Princess\decomp\unity\XenaUnity`.
Проект уже создан; новый проект через New создавать не требуется.
В списке редакторов нужен установленный `Unity63\Editor\Unity.exe`, версия
6000.3.25f1. Если Hub его не показывает, добавьте через **Installs → Locate**.

Можно открыть проект напрямую из корня папки игры: **Open-Xena-Unity.cmd**
открывает сцену модели, **Open-Xena-Level-01.cmd** — сцену первой локации.
Первое открытие требует завершения импорта. Лог обычного запуска сохраняется
в `decomp/build/unity-import/interactive-editor.log`.
Обе сцены уже созданы настоящим Editor. Команды открывают существующие сцены.

**Preview-Level-01.cmd** открывает отдельный просмотр ресурсов в Chrome
(или Edge, если Chrome отсутствует). Этот запуск не зависит от ассоциации `.html`
в Windows. Проверены запуск CMD из папки с пробелами и отображение локации в Chrome.

**Preview-Xena-Unity.cmd** запускает отдельный Windows x64 просмотрщик без Hub
и Editor. Сборка и настоящий запуск прошли проверку; доступны все 81 клип,
пауза, просмотр кадров, поворот и переключение текстур. Подробнее:
[Windows-просмотрщик](windows-asset-preview.md).

Дополнительно подготовлена первая локация: `Assets/Imported/Level01`, 74 меша,
3995 треугольников, исходная расстановка объектов и целочисленная сетка запроса
высоты. Меню **Tools → Xena → Create Level 01 Resource Preview Scene** предназначено
для отдельного просмотра локации. Это ещё не игровая сцена. Подробности и границы
проверок: [аудит локации](level-resource-audit.md).
Дополнительно рядом с моделью подготовлен `Lighting.json`: оригинальные цвета
2936 вершин из LGT, отдельно от яркости. Данные проверены по RAM всех частей
модели. Импортёр переносит цвета в Mesh.colors32, шейдер применяет исходную
модуляцию RGB, а в Play доступны переключатель освещения и ползунок яркости.
Нейтральная яркость — 0; значение +35 проверено по сохранённому запуску игры.
Все 35 955 компонентов импортированного Mesh проверены. GPU-проверка сравнивает
три режима локации и известные RGB-значения тестовой поверхности.
Рядом также подготовлены `Flags.json` и `Water.json`: проверенные категории
объектов, исходное/эффективное положение и таблица волны. Пока Unity использует
исходные позиции и статическую воду; ручной просмотр волны и привязки к земле
доступен в `Preview-Level-01.cmd`.
`Spawns.json` содержит 37 исходных записей PLRS. Их декодирование и связь с
живыми объектами проверены оригинальным кодом; 18 записей являются генераторами.
Браузер показывает диагностические точки, Unity пока не создаёт по ним NPC или ИИ.

В `build/unity-import/api-compilation.json` записан PASS компиляции настоящих
Unity API. `.NET`-проверка сравнила дополнительно 95 880 значений геометрии локации
и 1387 результатов C#-запроса высоты с исходными MIPS-инструкциями. Полный импорт
по-прежнему подтверждается только отдельным `editor-verification.json`.

Открыть в Unity Hub каталог `unity/XenaUnity`. Указана базовая версия
6000.3.25f1; используется Unity 6.3 LTS. Проект подключает локальный
пакет `unity/Packages/com.xena.original-assets` и его зависимость URP 17.3.0.
Unity Package Manager должен получить URP, если пакет ещё не закеширован.
Установленный Editor находится в папке `Unity63` рядом с `decomp`.

После импорта выбрать **Tools → Xena → Create Asset Preview Scene**, затем Play.
Сцена создаётся в `Assets/Scenes/XenaAssetPreview.unity`. Если сцена уже
существует, команда открывает её, сохраняя изменения пользователя.
В интерактивном режиме Unity сначала предлагает сохранить текущую сцену.

В Play доступны переключение клипов, пауза, кадр, поворот модели и оригинальные
либо 4× текстуры. Это просмотр ресурсов, а не контроллер персонажа или бой.

Пакет подготовлен для сборки следующих нативных ассетов:

- Main GameObject, автоматически преобразуемый ScriptedImporter в модель-prefab.
- 33 Mesh с 426 треугольниками и исходной иерархией частей.
- 81 AnimationClip с дискретными STEP-кривыми и последним удерживаемым кадром.
- 3 исходные и 3 увеличенные Texture2D, точечная фильтрация, alpha cutoff.
- Два набора материалов и собственный unlit-шейдер для URP.

Механизм prefab/subasset соответствует
[Unity Scripted Importers](https://docs.unity3d.com/6000.3/Documentation/Manual/ScriptedImporters.html).
Локальный пакет подключён относительно каталога Packages, как описано в
[UPM local paths](https://docs.unity3d.com/6000.3/Documentation/Manual/upm-localpath.html).
Создание URP-ассета использует публичный
[UniversalRenderPipelineAsset.Create](https://docs.unity3d.com/Packages/com.unity.render-pipelines.universal@17.3/api/UnityEngine.Rendering.Universal.UniversalRenderPipelineAsset.html).

## Подготовить данные повторно

Из корня `decomp/`:

```powershell
node tools/export_xena_unity.mjs
node tools/prepare_unity_project.mjs
node tools/check_unity_assets.mjs
```

Или пересобрать предыдущие этапы вместе с Unity-экспортом:

```powershell
node tools/build_xena_assets.mjs --unity
```

В `.xenamodel` сохранены уже проверенные данные glTF, адаптированные под
JsonUtility: сериализуемые классы и одномерные массивы, без jagged-массивов
и словарей. Ресурс и PNG копируются в `Assets/Imported/Xena/`, исключённый
из Git. Импортёр читает эти PNG напрямую и создаёт Texture2D-subassets,
поэтому не зависит от их TextureImporter-настроек.

Преобразования glTF → Unity:

| Данные | Преобразование |
| --- | --- |
| Положение / нормаль | `(x,y,z) → (x,y,-z)` |
| Quaternion | `(x,y,z,w) → (-x,-y,z,w)` |
| UV | `(u,v) → (u,1-v)` |
| Треугольник | `(0,1,2) → (0,2,1)` |
| Scale | Без изменения |

Масштаб 400 исходных единиц/м и частота 30 шагов/с остаются настройками
предпросмотра, а не измеренными параметрами оригинальной игры.

## Что уже проверено

`tools/check_unity_assets.mjs` запускает локальный .NET 9 SDK без NuGet-источников.
Скомпилированы настоящие общие C#-классы документа и его валидатор, используемые
импортёром. Независимая C#-программа прочитала экспорт и исходный glTF/bin:

- 67 узлов, 33 mesh, 426 треугольников, 81 клип, 1674 исходных кадра.
- 553 183 сравнения чисел: начальные трансформации, геометрия, нормали,
  UV, порядок индексов, времена и все каналы анимаций.
- Отклонены цикл в иерархии, неправильный индекс вершины, обрезанный канал,
  ненормализованный quaternion, выход пути текстуры из каталога, NaN и
  отсутствие исходной текстуры.
- Roslyn проверил синтаксис всех пяти C#-файлов пакета по правилам C# 9.
- Сборка общей C#-части: 0 ошибок и 0 предупреждений.

Результат: `build/unity-import/dotnet-verification.json` — PASS.
**Это не компиляция Unity-зависимых классов и не исполнение импортёра.**
Никаких поддельных Unity API-заглушек для получения зелёной сборки не использовалось.

## Запустить настоящую проверку Unity

Когда доступен Unity.exe:

```powershell
node tools/run_unity_import.mjs --editor "../Unity63/Editor/Unity.exe"
node tools/run_unity_import.mjs --editor "../Unity63/Editor/Unity.exe" --render
```

Можно задать `UNITY_EDITOR` вместо аргумента. Wrapper не устанавливает Unity,
а запускает указанный редактор в batchmode с отдельным журналом.

`XenaImportVerification.RunBatch` должен:

1. Принудительно импортировать `.xenamodel`.
2. Проверить количество настоящих Mesh, треугольников и AnimationClip.
3. Для всех 81 клипа сбросить исходные трансформации перед каждым кадром,
   вызвать `AnimationClip.SampleAnimation` и сравнить все анимированные свойства.
4. Создать/открыть сцену с URP, камерой и моделью.
5. Записать `build/unity-import/editor-verification.json` и завершиться с
   ненулевым кодом при ошибке.

Лог: `build/unity-import/editor.log`. Wrapper считает запуск успешным только
при нулевом коде редактора и отчёте PASS. Вызов без найденного редактора
завершается кодом 2 с явным сообщением, без ложного PASS.

Обычная batch-проверка использует `-nographics`. Отдельный `--render` запускается
с GPU, рендерит сцены через URP SingleCameraRequest и сохраняет восемь PNG.
Он проверяет непустые кадры, отсутствие ошибочного розового материала, компиляцию
шейдера и различие оригинальной/4× текстур. Дополнительно проверяются LGT,
яркость +35 и две RGB-пробы; всего сохраняются восемь PNG. Лог: `render-editor.log`.
Полное сравнение поз, прозрачности чакрама и отсечения граней с оригиналом ещё
требует отдельной проверки.
Эталон: `build/xena-preview/preview.html` и native-референсы предыдущего этапа.

Последняя проверка LGT выполнялась в отдельной копии проекта
`unity/XenaLightingVerification`, сохранив сцены основного проекта. Wrapper
поддерживает `--project unity/XenaLightingVerification` для такого запуска.
Основной Editor не запускался и его сцены не перезаписывались.
