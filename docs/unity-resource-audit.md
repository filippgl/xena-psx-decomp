# Unity: аудит ресурсов и анимаций — этап 0

Дата: 2026-10-22. Это первый статический аудит локальной копии игры, а не
подтверждение готовности импортёра или завершения этапа 0.

Продолжение 2026-10-22: восстановлен поток кадров SMA и структура SMI;
подробности и границы проверки в [описании формата](formats/sma-smi.md).
Все 81 клип / 1674 кадра проверены по исходным MIPS-инструкциям обработчика.
Ниже сохранены исходные результаты первого прохода; прежние открытые
вопросы о таблице, кадрах и иерархии уточнены в новом описании.

## Воспроизведение

Из каталога `decomp/`, Node.js 22 (без дополнительных зависимостей):

```powershell
node tools/audit_assets.mjs --disc "../Xena Warrior Princess.bin"
```

Результат: `build/asset-audit/manifest.json`. Файл содержит метаданные, хеши,
заголовки, проверки границ TMD и таблицы SMA; сами ресурсы не экспортируются.
Текущая Windows Python `.venv` неработоспособна: она ссылается на недоступный
Python310. Поэтому новый аудит не зависит от неё.

## Подтверждено чтением данных

- Диск уже извлечён существующим инструментом `tools/extract_disc.py`.
- `disc/filelist.txt`: XENA.UDA начинается на абсолютном LBA 475,
  размер 31 535 148 байт. Все эти байты сравнены с MODE2 Form1-секторами BIN:
  полное совпадение.
- Исполняемый файл — PS-X EXE. Размещение индекса и алгоритм хеширования
  переиспользованы из `tools/uda_find.py`: 1322 записи по 16 байт с адреса
  `0x800D5424`, веса с `0x800DA6C4`.
- 1300 записей целиком помещаются в XENA.UDA. Остальные 22 лежат вне архива;
  это не следует считать повреждением. Например, записи видео указывают на
  отдельные области диска. Их содержимое этим инструментом не разбирается.
- Для 222 записей найдены имена-кандидаты из строк EXE, ISO-листинга,
  исторических журналов и проверяемых шаблонов. Индекс хранит хеши, поэтому
  совпадение имени по хешу не является абсолютным доказательством имени.
  Несколько кандидатов и повторные записи сохраняются, а не затираются.
- 316 ресурсов имеют начальное слово `0x41`, 114 — `0x10`.
  Это сигнатуры-кандидаты TMD и TIM; полный разбор всех форматов не выполнен.
- Найден 21 `LEVEL.TMD`: 01–08, 10–12, 15–18, 20–22, 24–26.
  Это список найденных ресурсов, а не доказательство числа сюжетных уровней.

Контрольные SHA-256:

```text
xena.exe  4c429d2036efda06123225c8d90b2b5b1065a26867cc920b27fef8dcd0139e1c
XENA.UDA  de9f5d8de10dae4c0730084d8068d9471feec39588dbc6a154e83a97a6272bc8
```

## Набор ресурсов Зены

Пути относительно `DATA\LEVELS\`. LBA абсолютные, размер в байтах.

| Ресурс | LBA | Размер | Результат проверки |
| --- | ---: | ---: | --- |
| XENA.TMD | 811 | 18 760 | Заголовок 0x41, flags=0, 33 объекта |
| XENA.SMA | 821 | 173 572 | 146 слотов, 81 ненулевой |
| XENA.SMI | 906 | 664 | Найден; семантика полей ещё не восстановлена |
| XENA.STM | 785 | 52 344 | Найден; контейнер ещё не разобран |
| CHAKRAM.TMD | 780 | 1 972 | Заголовок 0x41, 2 объекта |
| CHAKRAM.SMI | 781 | 44 | Найден |
| CHAKRAM.STM | 777 | 4 680 | Найден |

Кандидат `DATA\LEVELS\CHAKRAM.SMA` отсутствует в индексе.
Это не означает отсутствие всей логики полёта чакрама: алгоритм находится
в игровом коде, а поведение без SMA нужно проверять отдельно.

Для XENA.TMD проверена стандартная относительная адресация от `file+12`:
все диапазоны вершин, нормалей и последовательности пакетов примитивов
33 объектов укладываются в ресурс. Суммарно 369 записей вершин и 426
примитивов. Это не число уникальных вершин или треугольников: индексы,
режимы примитивов, UV, материалы и иерархия ещё не проверены.

Первый уровень: `DATA\LEVELS\01\LEVEL.TMD`, LBA 3078, 160 920 байт,
74 объекта в заголовке; `LEVEL.STM`, LBA 2909, 338 216 байт.

## Что известно об анимациях

Источник: `asm/nonmatchings/game/func_80069C5C.s`.

- В `0x8006A020–0x8006A084` загрузчик выбирает имя `.SMA` и получает данные.
- В `0x8006A094–0x8006A10C` он обходит ровно `0x92` (146) указателей,
  начиная с `file+4`. Нулевые элементы пропускает; к ненулевым прибавляет
  адрес `file+4`. Значит, на диске это относительные смещения, а не
  абсолютные PS1-адреса.
- Из каждой ненулевой записи загрузчик читает `u16` по смещению `+4`
  и суммирует значения. Значение похоже на количество кадров, но до
  проверки потребителя обозначается как поле заголовка.
- В XENA.SMA первое слово равно 146. Все 81 ненулевое смещение ведут
  за таблицу и позволяют прочитать минимум 6 байт заголовка внутри файла.
  Это проверка границ заголовков, не проверка всех кадров.
- `func_80041568`, `0x8004159C–0x800415BC`, выбирает элемент таблицы
  по номеру действия (`file+4+action*4`), что связывает таблицу с действиями
  персонажа. Не каждый игровой state обязательно равен номеру клипа.

Примеры из XENA.SMA:

| Слот | Смещение от начала файла | Три первых u16 |
| --- | ---: | --- |
| 0x00 | 588 | 0x4144, 0x0200, 27 |
| 0x14 | 3 042 | 0x4144, 0x0200, 5 |
| 0x2F | 31 322 | 0x4144, 0x0200, 44 |
| 0x51 | 98 446 | 0x4144, 0x0200, 15 |
| 0x61 | 125 742 | 0x4144, 0x0200, 18 |
| 0x64 | 130 660 | 0x4144, 0x0200, 21 |

Пока не установлено, используются ли матрицы частей тела, скелетные
трансформации, вершинная анимация или сочетание способов. 33 объекта TMD
сами по себе не доказывают наличие 33 костей. Unity Animator и Humanoid
до восстановления этой связи выбирать преждевременно.

## Порядок дальнейшего исследования

1. Проследить потребителя SMA после выбора слота: размер записи кадра,
   преобразования частей TMD, интерполяция, root motion и частота обновления.
   Проверить SMI рядом с загрузкой в `func_80069C5C`.
2. Разобрать STM: определить, где находятся изображения, палитры, страницы
   VRAM и таблица материалов. Не трактовать STM как обычный TIM по расширению.
3. Экспортировать статическую XENA.TMD и один кадр SMA в диагностический
   формат. Затем последовательность idle и бега; сравнить позы с текущим
   PC runtime и оригиналом в эмуляторе.
4. После доказательства анимационного импорта изучить геометрию коллизий,
   координаты, масштаб, триггеры и события первого уровня. Эти системы
   данным аудитом ещё не идентифицированы.

Условие следующего контрольного результата: оригинальная модель с
корректными материалами воспроизводит минимум idle и бег, а кадры и
движение сопоставлены с оригиналом. До этого полноценный Unity-контроллер
и боевую систему разрабатывать рано.

Остаются невыполненными части этапа 0: видеореференсы из эмулятора,
карта коллизий и скриптов, точные алгоритмы движения/боя/чакрама,
аудит внешнего проекта рекомпиляции и лицензий. Сроки полного переноса
по текущим данным уточнять пока нельзя.
