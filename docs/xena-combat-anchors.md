# Исходные точки контакта: границы проверки

`node tools/verify_xena_combat_anchors.mjs` использует 485 RAM-снимков двух
боевых сценариев и исполняет оригинальную функцию вращения `0x8008E40C`.
Отчёт и извлечённые определения остаются локально:
`build/combat-geometry/anchors-verification.json`.

Подтверждено:

- У класса Зены по `+3C` находится список из девяти записей по 16 байт,
  заканчивающийся индексом части `-1`. Каждая запись содержит индекс части
  (`int16`), пока не интерпретированное полуслово и три `int32` смещения.
- `0x8006A6E8` использует матрицы частей по `context+2C`, шаг 32 байта.
  Для обычного режима точка равна `translation - floor(rotation * offset / 4096)`.
  В функции есть отдельный режим ссылки на вершину модели при первом значении
  смещения `80000`; в этих девяти записях он не встречается и инструмент его
  намеренно не объявляет проверенным.
- 4365 вращений, 13 095 компонентов и 270 630 исходных MIPS-инструкций совпали
  с расчётом инструмента. В 480 непрерывных парах снимков все 4320 текущих точек
  совпали с нативным буфером `actor+12C`.
- Снимки содержат уже перемещённые матрицы, а буфер точек относится к позиции
  до перемещения корня. Используется независимо сохранённая позиция корня
  предыдущего снимка, без подгонки смещения по результату. Для пяти начальных
  снимков отдельных интервалов проверяется вращение, но не буфер.

Первоначальное прямое сравнение в мировых координатах не прошло на кадре 9006:
все девять точек отличались на один и тот же вектор `(-6, 0, -9)`. Это в точности
противоположность измеренного перемещения корня между кадрами 9004 и 9006.
Проверка порядка обновления затем прошла на всех непрерывных парах.

`actor+12C` и `actor+130` меняются местами один раз за нативный такт. Однако
предыдущий буфер нельзя считать неизменной копией предыдущего снимка: найдено
144 отличия, в частности обнулённые X при сохранённых Y/Z. Они записаны в
`previousBufferAudit` как **UNRESOLVED** и не входят в успешную проверку.
`0x80035070` действительно использует ненулевой первый компонент как условие
передачи предыдущей точки в `0x80070D84`; точное место и условия обнуления
нужно исследовать отдельно.

Эти точки используются не только боем: контроллер также передаёт некоторые
из них обработчикам шагов. Сами точки не задают полные хитбоксы. Радиусы,
активность атаки, обработка цели, урон и реакции пока не проверены.
Учебные попадания Unity продолжают использовать временные правила; автоматической
замены их на исходные столкновения этим аудитом не производится.

Проверен существующий `build/port/xena-console.exe`, время изменения
`2026-10-22T18:11:35.259Z`; нативные исходники и оригинальный EXE не изменялись.
