# Xena SMA / SMI: установленная часть формата

Проверено 2026-10-22 на локальной SLUS-00977. Все числа little-endian.
Реализация: `tools/lib/xena_animation.mjs`. Это форматный декодер обычного
воспроизведения, не Unity Animator и не полная реализация игрового runtime.

## SMI: исходные трансформации и иерархия

Для XENA.SMI первые 660 байт — 33 записи по 20 байт, по числу объектов TMD.
Последние 4 байта ресурса пока не интерпретируются.

| Смещение в записи | Тип | Назначение |
| --- | --- | --- |
| +0, +4, +8 | s32 × 3 | Положение части |
| +12, +14, +16 | s16 × 3 | Три компоненты вращения |
| +18 | s16 | Индекс родительской части; −1 для корня |

Доказательства: `func_80069C5C` копирует `objectCount*20` байт из SMI в
изменяемый массив (`0x8006A1D8–0x8006A214`), находит корень по −1
(`0x8006A230`) и строит списки детей сравнением поля +18 с индексом
родителя (`0x8006A30C–0x8006A378`). У Зены один корень — объект 27;
циклов и выходящих за диапазон родителей нет.

Это иерархия частей исходной TMD. Система весов вершин SkinnedMeshRenderer
данными проверенного пути не подтверждается. Начальный вариант импорта
может использовать отдельные Mesh-части с Transform, но корректность
мировых матриц и привязки геометрии ещё необходимо доказать.

## SMA: таблица клипов

- +0: u32, у Зены 146.
- +4: 146 элементов u32; 0 означает пустой слот.
- Ненулевой элемент — смещение относительно `file+4`.

Загрузчик `func_80069C5C`, `0x8006A094–0x8006A10C`, явно обходит
146 элементов и преобразует ненулевые смещения в указатели.

Заголовок каждого найденного клипа:

| Смещение | Тип | Значение / назначение |
| --- | --- | --- |
| +0 | u16 | 0x4144 |
| +2 | u16 | 0x0200 |
| +4 | u16 | Количество шагов кадров |
| +6 | u16 | Неинтерпретируемое поле |
| +8 | поток | Записи кадров |

Количество кадров подтверждено не только границами файлов:
`func_8004180C`, `0x80041FE4–0x80042008`, сохраняет поле +4 в
`context+0x22`, устанавливает поток в `clip+8`, обнуляет счётчик
`object+0xE6`. `func_80069B80` увеличивает счётчик и обрабатывает кадр.

Каждый кадр начинается с двух u16: пока неинтерпретируемого поля и числа
команд. Затем идут команды переменной длины. Частоту кадров в секундах
из этих полей не выводим: игровой планировщик отдельно не проверен.

## Команды обычного воспроизведения

Источник: оригинальный обработчик `func_80069040`.
Начальное слово u16: `type = word & 7`, `target = word >> 8`.
Изменения накопительные; для воспроизведения кадра N нужны предшествующие
кадры или заранее рассчитанная поза. Вращения переполняются как 16-битные,
положение — как 32-битное.

| Тип | Назначение в клипах Зены | Количество команд |
| --- | --- | ---: |
| 1 | Изменение положения / вращения указанной части | 5182 |
| 5 | Переключение видимости части | 6 |
| 6 | Служебные поля контекста или изменение вращения | 1057 |
| 7 | Пакет сжатых изменений трансформаций нескольких частей | 1593 |

Для типа 1 маска `0x38` выбирает компоненты. При ненулевой маске `0x80`
выбирает вращение вместо положения, `0x40` — присваивание вместо
прибавления. Компоненты вращения в потоке идут в порядке полей
`+14, +12, +16`; компоненты положения — `+0, +4, +8`.
Если маска нулевая, изменяются все шесть компонент: `0x40` выбирает
16-битные значения, иначе используются знаковые 8-битные дельты.

У типа 7 без `0x08` старший байт — число изменяемых частей. Обход идёт
по порядку объектов, пропуская корневую запись с parent=−1. Основной
вариант пакует три знаковые 4-битные дельты вращения и степень сдвига
в u16. Признак `(packed & 0xFE) == 0x7E` выбирает расширенный вариант
из двух слов со знаковыми 8-битными компонентами, умноженными на 16.
Младший бит добавляет слово с дельтами положения. Точные маски и сдвиги
зафиксированы в декодере и проверены исполнением исходных инструкций.

Тип 2 и тип 7 с `0x08` в обработчике меняют вершины. В 81 клипе Зены
они не встречаются; декодер явно останавливается при их обнаружении.
Поддержку анимаций всех остальных персонажей это исследование не доказывает.

## Проверка по оригинальному машинному коду

```powershell
node tools/audit_assets.mjs --disc "../Xena Warrior Princess.bin"
node tools/inspect_xena_animation.mjs
node tools/verify_xena_animation.mjs
```

Проверяющий инструмент исполняет инструкции оригинальной функции
`0x80069040` из xena.exe в небольшом MIPS-интерпретаторе. Это независимый
путь от форматного декодера: он читает бинарные инструкции, включая
таблицу переходов, ветвления и delay slots. Оба пути начинают каждый
клип с одной и той же SMI, режим `context+0x2A=0`.

Результат PASS:

- 81 клип, 1674 кадра, 7838 команд; 3 297 597 исходных инструкций.
- Совпадает количество байт, потреблённое каждой командой.
- Для каждого кадра совпадают все положения, вращения, родители,
  состояния видимости и обработанные служебные поля.
- Между концами разобранных клипов и следующими клипами нет остатка байтов.
- Отклоняются обрезанная SMA, смещение за границу и циклическая SMI.

Продолжение: восстановлены мировые трансформации и STM; получен
текстурированный glTF и предпросмотр с оригинальным вариантом и 4×.
См. [результат, команды и границы проверок](../xena-asset-preview.md).
Форматный декодер принимает исходную маску видимости аргументом.
Xena-инструменты начинают клипы с подтверждённой в native idle маски:
части 31 и 32 скрыты. Внутри runtime хранится HIDDEN, поэтому записанный
командой 5 ноль означает видимость, единица — скрытие.

Вызов поиска mesh `func_800A5300` для команд видимости заменён заглушкой:
возвращаемое значение в этой ветви не используется. Полный рендерер,
контроллер персонажа и переключения клипов здесь не выполняются.
Интерпретатор предназначен только для достигнутых инструкций этой функции;
неизвестные инструкции приводят к ошибке.

Артефакты в игнорируемом `build/animation-audit/`: `summary.json`,
`slot-XX.json` с покадровыми позами и `verification.json`.
Файлы поз содержат извлечённые игровые данные и не предназначены
для добавления в публичный репозиторий.

Проверка матриц завершена: исходные `func_80014DE4/80014E78` обходят
иерархию, меняют знак первой компоненты вращения и вызывают `func_80014BE4`.
Последняя соответствует `Ry(y) * Rx(-x) * Rz(z)` с точной таблицей синусов
и косинусов по `0x800CE8B8` и последовательностью Q12-округлений.
Композиция `func_80014AB8` использует s16 локальные положения, Q12 для
вращения и s32 для положения результата. Все 55 242 матрицы совпали
с исполнением исходных инструкций и необходимых GTE GPF/MVMVA операций.
Внешняя матрица в полной проверке — единичная, дополнительного масштаба нет.
Отдельно совпали 66 матриц двух native-кадров с их настоящей внешней матрицей.

Остаётся проверить физический масштаб, переходы с сохранением предыдущей позы,
root motion, специальные режимы `context+0x2A` и визуальное совпадение
с PS1-референсом. В частности, независимый старт из SMI не доказывает
корректность игровых переходов между анимациями.
